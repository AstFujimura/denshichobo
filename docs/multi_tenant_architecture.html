7デプロイ

顧客ごとのEC2へ同じ変更を配布する運用から、共通アプリへの1回のデプロイへ変わる。

以前 — 顧客別EC2へ配布

開発環境の変更Gitへ反映
AWS Systems ManagerRun Command等でGitコマンドを一括実行
EC2 顧客Agit pull / 更新作業
EC2 顧客Bgit pull / 更新作業
EC2 顧客Cgit pull / 更新作業
  • EC2台数分の更新結果を確認
  • 一部サーバーだけ失敗する可能性
  • 顧客ごとにコード差分が生じる可能性
→

今後 — 共通アプリへ1回

開発環境の変更Gitへ反映
共通 EC21系統のLaravelアプリを更新
顧客A同じコード
顧客B同じコード
顧客C同じコード
  • デプロイ対象は共通アプリの1系統
  • 顧客別EC2へのGit一括実行は不要
  • 全テナントが同一バージョンを利用
変更点: AWS Systems Manager（SSM）Run Command等を使って各EC2でGitコマンドを一括実行する運用は不要になる。
デプロイ対象は、顧客別EC2群から共通アプリ1系統へ変わる。

8バックアップ

AWS Backupで取得するアプリサーバーのイメージを、顧客別から共通サーバー1系統へ集約する。

以前 — EC2ごとのAMI

AWS Backup顧客別EC2をバックアップ
AMI A顧客A
AMI B顧客B
AMI C顧客C
  • EC2台数に応じてバックアップ対象が増加
  • 復旧手順も顧客ごとに管理
→

今後 — 共通EC2のAMI

AWS Backup共通EC2をバックアップ
共通バックアップイメージアプリサーバーは1系統
  • AMIの取得対象を共通EC2へ集約
  • 復旧するアプリ環境も1系統
  • バックアップ設定・監視を簡素化
注意: 共通EC2のAMIとは別に、制御DB・各テナントDB・S3等のデータバックアップは継続して管理する。
AWS Backup: アプリサーバーのバックアップ対象を顧客数分から共通EC2へ集約
